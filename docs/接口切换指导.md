
# 开发与部署指南 (Development & Deployment Guide)

## 🌟 接口开发模式 (API Strategy)

本项目采用 **模块化混合数据源** 策略。不再区分全局的“Mock模式”或“真实模式”，而是允许你为每个功能模块单独指定数据源。

### 1. 核心原理
前端配置了两个主要的代理路径：
*   `/api` -> 指向真实后端服务器 (Default)
*   `/mock-api` -> 指向本地 `json-server`

### 2. 如何配置
打开 `src/services/mockApi.ts`，你会看到如下配置：

```typescript
const MODULE_CONFIG = {
  PROJECTS: 'mock',      // 此模块使用 mock 数据 (db.json)
  DIARY: 'real',         // 此模块使用 真实后端接口
  AUTH: 'real',          // 此模块使用 真实后端接口
};
```

*   **默认行为**：任何未在配置中出现的模块，或者配置为 `'real'` 的模块，都会请求真实后端。
*   **开发新功能**：当你开发新功能且后端未就绪时，将其设为 `'mock'`，并在 `db.json` 中添加模拟数据。
*   **联调**：后端接口完成后，只需将配置改为 `'real'` (或删除配置项) 即可无缝切换。

### 3. 启动项目
你需要同时运行前端和 Mock 服务（如果你用到了 Mock 模块）：

```bash
# 窗口 1: 启动 Mock 数据服务 (3001端口)
npm run server

# 窗口 2: 启动前端开发服务
npm run dev
```

### 4. 环境变量 (.env)
你可以在 `.env` 或 `.env.local` 中指定你的真实后端地址：

```ini
# 真实后端地址 (你的 Java/Go/Node 服务)
VITE_API_TARGET=http://localhost:8080

# Mock 服务地址 (通常不需要改)
VITE_API_TARGET_MOCK=http://localhost:3001
```

## 🛡️ 请求防抖与节流

我们在 `src/services/axiosInstance.ts` 中集成了自动的请求取消机制：

*   **机制**：当同一个接口（URL + Method + 参数完全一致）在上一个请求未完成时再次被触发，**上一个请求会被自动取消 (Cancel)**。
*   **目的**：防止用户快速点击按钮导致的重复提交，以及防止旧数据的竞态问题（Race Condition）。
*   **例外**：如果某些接口允许并发重复请求，请在请求 config 中传入 `allowDuplicate: true`。
