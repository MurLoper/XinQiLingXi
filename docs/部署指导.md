
# 📦 构建与配置指南 (Build & Configuration Guide)

本文档旨在帮助开发者快速理解项目的运行脚本、环境变量配置以及 Mock 数据策略。

---

## 1. 🚀 常用指令 (Scripts)

| 指令 | 对应命令 | 说明 | 适用场景 |
| :--- | :--- | :--- | :--- |
| **`npm run dev`** | `vite` | 启动前端开发服务器 (默认端口 5173) | **日常开发** |
| **`npm run server`** | `json-server ...` | 启动本地 Mock 数据服务器 (端口 3001) | **日常开发** (需配合前端运行) |
| **`npm run build`** | `tsc && vite build` | 执行类型检查并打包生产环境代码 | **生产部署** |
| **`npm run preview`** | `vite preview` | 预览 `dist/` 目录下的打包结果 | **检查打包** |
| **`npm run type-check`**| `tsc --noEmit` | 仅执行 TypeScript 类型检查，不打包 | **代码质量检查** |

## 2. ⚙️ 环境变量配置详解 (Environment Configuration)

Vite 使用 dotenv 加载环境变量。以下是 4 种文件的具体用途和优先级（**越靠前优先级越高**）：

### 🛠️ 开发环境 (`npm run dev`) 加载顺序

1.  **`.env.development.local`** (最高优先级)
    *   **用途**：**个人本地开发专用覆盖**。
    *   **包含内容**：你自己的 API Key、本地测试用的后端地址。
    *   **Git 状态**：🚫 **被忽略** (不要提交)。
    *   **示例**：
        ```ini
        VITE_GEMINI_API_KEY=AIzaSy_MY_PRIVATE_KEY
        VITE_API_TARGET=http://192.168.1.5:8080 (调试同事电脑的接口)
        ```

2.  **`.env.development`**
    *   **用途**：**团队共享的开发环境配置**。
    *   **包含内容**：开发环境的公共后端地址、非敏感的公共 Key。
    *   **Git 状态**：✅ **已提交** (全员共享)。
    *   **示例**：
        ```ini
        VITE_API_TARGET=http://dev.xinqilingxi.com (开发测试服)
        ```

3.  **`.env.local`**
    *   **用途**：**所有环境的本地通用覆盖**。
    *   **包含内容**：无论 dev 还是 build 都想生效的本地配置。
    *   **Git 状态**：🚫 **被忽略**。

4.  **`.env`** (最低优先级)
    *   **用途**：**项目兜底默认配置**。
    *   **包含内容**：所有变量的默认值。
    *   **Git 状态**：✅ **已提交**。
    *   **示例**：
        ```ini
        VITE_API_TARGET_MOCK=http://127.0.0.1:3001
        ```

### 🚀 生产打包 (`npm run build`) 加载顺序

1.  **`.env.production.local`** (最高优先级，本地打包时用，CI/CD通常不用)
2.  **`.env.production`** (生产环境标准配置，**已提交**)
3.  **`.env.local`**
4.  **`.env`**

---

### 📝 核心变量清单

请确保在你的 `.env.development.local` 或 CI/CD 环境变量中配置了以下内容：

| 变量名 | 必填 | 描述 | 示例值 |
| :--- | :--- | :--- | :--- |
| **`VITE_GEMINI_API_KEY`** | ✅ 是 | Google Gemini AI 模型的 API 密钥。 | `AIzaSy...` |
| **`VITE_API_TARGET`** | ❌ 否 | **真实后端**接口地址。 | `http://127.0.0.1:8080` |
| **`VITE_API_TARGET_MOCK`**| ❌ 否 | **Mock 服务**地址。 | `http://127.0.0.1:3001` |

## 3. 🛡️ Mock 与真实接口切换策略

配置位于源码：`src/services/mockApi.ts`

```typescript
// 修改此对象来决定每个模块走 Mock 还是 Real
const MODULE_CONFIG: Record<string, 'real' | 'mock'> = {
  PROJECTS: 'mock',      // 使用本地 db.json 数据
  DIARY: 'mock',         // 使用本地 db.json 数据
  AUTH: 'real',          // 使用 VITE_API_TARGET 指向的真实接口
  CITY_ANALYSIS: 'mock', // 使用代码中的模拟逻辑
};
```

## 4. 🚀 生产环境部署 (Deployment with Mock Data)

如果你希望在远程服务器上部署打包后的代码，**并且依然使用 db.json 作为数据源**。

### 步骤一：准备文件
上传以下文件到服务器目录（如 `/var/www/xinqilingxi`）：
1. `dist/` 文件夹（构建产物）
2. `db.json` （数据源）
3. `package.json` （用于安装依赖）
4. `ecosystem.config.cjs` （PM2 配置文件）

### 步骤二：PM2 配置文件 (`ecosystem.config.cjs`)
请在根目录下创建此文件，内容如下：

```javascript
module.exports = {
  apps: [
    {
      name: "xinqilingxi-mock-server",
      script: "npx",
      // --host 0.0.0.0 允许局域网或Nginx反向代理访问
      args: "json-server --watch db.json --port 3001 --host 0.0.0.0",
      env: {
        NODE_ENV: "production",
      },
      // 错误重启策略
      exp_backoff_restart_delay: 100,
      max_memory_restart: '200M'
    },
  ],
};
```

### 步骤三：启动服务
```bash
# 1. 安装生产依赖
npm install --production

# 2. 全局安装 PM2
npm install -g pm2

# 3. 启动 Mock 服务
pm2 start ecosystem.config.cjs
pm2 save
```

### 步骤四：配置 Nginx
```nginx
server {
    listen 80;
    server_name your-domain.com;

    # 静态资源
    location / {
        root /var/www/xinqilingxi/dist;
        index index.html;
        try_files $uri $uri/ /index.html;
    }

    # Mock 接口转发 -> 指向本地 3001
    location /mock-api/ {
        proxy_pass http://127.0.0.1:3001/; 
        proxy_set_header Host $host;
    }
    
    # 真实接口转发 -> 指向真实后端
    location /api/ {
        proxy_pass http://your-real-backend:8080/;
    }
}
```
